# 04: 完成后自动生成（接真 provider）

**What to build:** 每轮对话**完成**后，宿主自己发起一次 Card generator：它把最近这段会话压成紧凑的 user 提示、带上现有卡片，再连同前端透传的系统提示一起交给 provider，流式拿回的 op 直接进 03 的通道，右侧卡片随之自己长出来。用户不需要任何操作；而当他开始输入下一条 Prompt 时，这次生成立刻被掐断。卡片请求不写 Message history，也不进会话用量。

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] 触发矩阵成立：本轮 `completed` 才自动生成；`cancelled` 与失败不触发且保留上一版卡片；新建与恢复会话不触发
- [ ] 系统提示由前端在运行时按 catalog 生成并随请求透传，宿主不保存第二份组件描述；user 提示由宿主拼装（最近约二十条消息的投影、工具结果截断、现有卡片、本次触发原因）
- [ ] 生成走一条独立的 provider 调用：空工具集、保守的响应上限、独立的取消令牌与线程，配置沿用会话已解析的那一套
- [ ] 主 turn 一开始就取消在跑的生成（不阻塞命令线程），应用销毁时回收该线程；不新增生命周期状态，既有"运行中"语义仍只表示主 turn
- [ ] 生成进行中再次请求生成被明确拒绝（单飞）
- [ ] 该请求的 token 用量不计入会话累计、Usage HUD 与上下文百分比
- [ ] 用注入的假 provider 断言：op 行到达顺序、触发矩阵的四个分支、取消即时生效、单飞拒绝、响应上限被传入、模型没有任何输出时结束事件带失败标记
- [ ] 真实对话跑一轮后，右侧出现的卡片内容与本轮实际发生的事相关
