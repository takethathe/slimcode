# 05: Card kind 词表与多卡生命周期

**What to build:** 卡片从"只有一种"扩成固定词表的三类——任务看板、本轮结果、指标洞察；同一类再次生成是**替换**那张卡而不是再添一张，单会话最多三张、最近更新的排在前面、最久未更新的被淘汰。宿主在生成时把当前卡片一并给模型，让它能在看板上做增量更新，于是看板可以跨多轮持续存活。

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] 三类卡片类型在组件目录侧有各自的描述与约束，模型只能对其中之一输出 op，不能发明新类型
- [ ] 同一类型再次生成时整卡重置重建，面板里仍是三张而不是四张
- [ ] 单会话最多三张，按最近更新倒序展示；超出上限时最久未更新的一张被淘汰，且淘汰在宿主与面板两侧一致
- [ ] 生成请求携带当前卡片，模型对已存在的同一类型卡做增量编辑（看板在多轮之后仍保留早先的条目，除非被明确改写）
- [ ] 宿主侧测试覆盖：同类型替换而非追加、超限淘汰、排序、跨轮增量更新；面板侧覆盖三类卡片的渲染与排序
- [ ] 连续对话三轮，看板累积演进且没有被两张结果卡挤掉
