# 03: 卡片事件通道与宿主的镜像真相

**What to build:** Tauri 宿主拥有卡片的唯一真相：它把每条 op 应用到自己镜像的 Spec 上，同时把同一行原样推给 webview。前端启动后订阅一次，订阅命令返回当前全量快照，之后收到"开始 / op / 结束 / 全量对齐"四类事件。此切片用一条**合成的 op 流**（不调用模型）打通 宿主 → webview → 渲染 的完整路径，并验证窗口重载后由快照恢复同一张卡。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 宿主侧的 op 应用与前端同语义：目标缺失也写入、自动创建父路径、缺路径删除静默，且与前端使用同一条换行切分与残行缓冲规则
- [ ] 同一串 op 分别喂给宿主与前端两个实现，最终 Spec 相等（共享 fixture 的宿主侧断言）
- [ ] 宿主先转发再应用，任何宿主侧异常都不会吞掉一行前端本可渲染的 op
- [ ] 订阅命令返回当前全量快照，随后按"开始 → 若干 op → 结束"的顺序推送事件；op 以单行 JSON 字符串原样过线，不解构成对象
- [ ] 卡片在此阶段只有一个固定类型，保存在宿主内存中；切换会话时清空
- [ ] 手动触发一条合成流可以端到端驱动面板生长；窗口重载后卡片由快照恢复
- [ ] 宿主侧测试覆盖：应用语义的边界用例、事件顺序、快照内容、切会话清空；控制器仍可离线测试（注入假 provider 与记录型接收端），GUI 的 Rust 门禁全绿
