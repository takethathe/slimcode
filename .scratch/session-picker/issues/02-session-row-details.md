# 02: 行变可辨认——标题、消息条数与修改时间

**What to build:** picker 的每一行左半边显示会话标题（没有标题记录时回退到 id）、右半边显示
`N msgs` 与修改时间（`1 msg` 用单数，时间形如 `2026-02-14 15:32`），整个列表按修改时间从新到
旧排列。这份信息来自对每份会话日志的一次流式扫描：日志头解析失败的文件直接从列表里消失，
消息条数按 record 的 `type` 判定（不整份 JSON 解析），标题取第一条 `title` record。

**Blocked by:** 01

**Status:** resolved

- [x] 行内容为 `title ?? id` + `N msgs` + 修改时间；`1 msg` 单数正确。
- [x] 列表按日志文件的修改时间降序；修改时间相同则按 id 降序（结果确定，可重复）。
- [x] 日志头无法解析的文件被跳过，不影响其余文件。
- [x] 条数等于日志里 `message` record 的条数：日志含未知 record 类型、坏行，或某条消息内容
      里恰好出现字面量 `{"type":"message"`（转义形式）时都仍然正确。
- [x] 没有 title record 的会话显示 id。
- [x] 每份日志只读一遍且逐行流式处理；打开 picker 的代价随日志行数增长，而不是随 store 配额增长。
- [x] 时间取自文件 mtime，用 UTC 时钟渲染，不做时区换算，不引入任何日期/时区依赖，也不用 unsafe。
- [x] 只返回 id 的旧读接口被摘要接口取代（既有隔离性测试迁移过去，断言不变的行为）。
