# Skills are frontmatter-driven, scope-discovered, and trigger via `/`; `disable-model-invocation` keeps them out of the system prompt

Skills reuse the slash (`/`) trigger shape already used by commands: a skill is a `SKILL.md` file whose YAML-style frontmatter carries `name`, `description`, and an optional `disable-model-invocation`. Skills are discovered from a user scope (`<home>/skills/`) and a project scope (`<cwd>/.slimcode/skills/`), with project winning on a name clash. A skill marked `disable-model-invocation: true` has its description omitted from the system prompt, so the model only runs it through an explicit `/name` trigger; skills without that flag are advertised in the system prompt. This keeps skills installable per user/project and discoverable through the same prediction path as commands, without coupling the command registry to file I/O.
